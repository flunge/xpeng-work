# 输出纪律（防长输出退化）

> 背景：2026-08-03 会话中模型多次出现长输出退化（反引号循环、乱码 token、畸形 tool call）。
> 根因=模型在长上下文下生成长内容时退化，非平台问题。本文件是硬约束，不是建议。

## 四条铁律

1. **一次只做一个动作**：单条回复最多一个 write/edit；不生成"表格+多文件edit+长JSON"复合回复。
2. **大 payload 先落盘**：写文件内容 >2KB 时，用 `write` 整文件写入，禁止在 `edit` 参数里内联大段文本；`oldText` 保持小而唯一。
3. **退化即中断**：输出中出现重复 token 循环/乱码时，立刻停止该轮，重发精简版本，不继续推进工具链。
4. **阶段节点即落账**：长会话每完成一个阶段就 git commit + 更新 `.claude/team/` 下的状态文档；关键节点建议用户新开会话，上下文重置。

## 配套使用习惯

- 工具输出节制：大结果集一律 `| tail -20` / `| head`，不全量进上下文。
- Base 操作脚本一律幂等（来源定位键去重），允许失败后放心重跑。
- 长会话遗留状态写进 `MEMORY_REBUILD_V2.md` 工具链状态段，跨会话可接续。
