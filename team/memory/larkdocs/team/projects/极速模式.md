## 一、背景目标

**项目定位**：支持特定客诉 case 的**快速生产 + 仿真验证**——仅跑预处理 + FeedForward（地面 RoGS + 背景 EvolSplat/SCube + 动态物体 SAM3D），绕开 3DGS 后训练，配合仿真渲染时带 Ref 图的 Difix 修复，把端到端从完整模式的 3-4 小时压缩到 **1.5-2 小时**（227 样本均值 91.4min、单 case 集中 90-120min）。闭环 pose 与实车越接近效果越好，适用范围为偏离实车轨迹不远的 case。*（来源：X6a2wQUV 交付文档 + WAS8wadJ 方案文档）*

**最终目标**：Q2 末稳定支撑常态化 badcase 生产验证、全链路时延 2h 以内。技术路径：预处理通过子模块并行/省略（SAM3D 与 MVSNet 并行、省去 trafficlight/depth/point/densifier）+DA3 替代 MVSA 降 20min +SCube 替代 EvolSplat 压缩预处理；仿真端通过 init_from_feedforward+Difix ckpt 渲染。CPU:GPU = 1:5 配比、每 case 独占一个 GPU 时最快。*（来源：WAS8wadJ 方案文档 + C6l2w9Yb 预处理调研）*

## 二、当前状态（截至 2026-07-03）

- **定论"默认打开"**（邓爽 6/17）：极速模式虽略低于正常模式但可接受、后续默认打开。
- **效率**：平均提速 **2.6 倍**（227 样本：极速 91.4min vs 普通 237.9min）；W27 端到端 2.5-3h（抛开等 GPU）、训练 1.5-2h、仿真 45min（极速与普通无区别）。
- **复现率**：业务场景相对复现率 **74%**（108 中 80）；全量市场综合折算 **51.8%**（普通 70% × 相对 74%）。
- **质量指标（闭环误差）**：39 case 数据集—feedforward+difix 加速度误差 0.128（vs 3dgs+difix 0.092、原图 0.075）、位置误差 0.048（vs 3dgs+difix 0.037）；19 case 数据集—加速度 0.151、位置 0.050。Bad Case 主因：仿真车偏离实车后 ref 图与真实图差距大、画面抖动/帧间一致性不足/虚影。合入测试 29 case 人工评审 good 17/bad 12。*（来源：VVCNwnV4 合入测试报告 + WAS8wadJ 方案文档）*
- **链路**：subrun/clip 迁 UCP 一段式；**仿真设置自适应**（无需人工设置）——7/1 理清上下游调度、无需后端/平台介入，7/3 自测通过、随后端发版携带。
- **预处理耗时分布**（13 clip 均值、单卡双任务 A100）：img 26min(35.5%) + mvsnet 20min(27.2%) + sam3d 8.9min(12.2%) + ground 8.8min(12%) + depth 4.2min + feedforward 2.3min + 其他 <2min ≈ **73.4min GPU 总计**。优化验证：降 Mask2Former 分辨率（v1）省 3%、bf16 混合精度（v2）省 17% 但分割 mIoU 降至 0.872；合并后 v3_A1024_Dbf16 平均 4623s（相对 dev 基线-5%、相对 v0-20%）。*（来源：C6l2w9Yb 预处理链路优化调研）*
- **管理**：李坤定极速模式长期在周二 WM 会收反馈、不 deadline 驱动、持续迭代。
- **风险 / 挑战**（截至 2026-07-24·W30）：🔵 **方向调整——极速模式不再作为独立产品推进**：用户满意度调研后李坤定调，把极速模式全部优化点合并进常规生产流程、消除双流程认知负担（李坤 7/20 承认已提速但使用率低是「产品能力与用户习惯的信息差」）；下列技术风险随之转为对常规流程的优化项（来源：算法组群/核心日会 7/20）。🔴 复现率上限受 feedforward 重建质量制约，仍是核心瓶颈；🟢 生产提速显著缓解——增量式生产（历史预处理+模型包缓存）单 clip 从 120min 缩至 17min（缩短 86%）、1000/2000 step 实验原视角明显收益（7/22–23）；🟡 渲染效果待 DFIX 接入优化（极速渲染与真值仍有明显差异）；🟡 质量——diff 训练仅 120+ 视频片段、缺 A100 无法大批量重训；🟡 生产报错以抛异常方式呈现——已由 3dgs 生产 agent 7/24 正式上线接管（周蔚旭为接口人、oom 及可忽略错误占比 >80% 自动处理），规范化风险大幅收敛。

## 四、后续规划

- **默认打开极速模式**，结合最新 NVFixer + 飞步给出新版本（周冯评估时间）。
- **质量提升**：争取 A100 / 匀 GPU 用于 Difix 大批量重训，改善近点模糊、前车情况。
- **预处理链路降耗**：① DA3 替代 MVSA 深度预测（接受长序列输入、预期单卡双任务 20min vs MVSA 40min）—初版 5.30、大批量训练版 6.30；② 子模块并行（SAM3D ∥ MVSNet）+ 省略 trafficlight/depth/point/densifier；③ SCube 替代 EvolSplat（已开发完成、待阿里适配 PPU）。优化目标：img+mvsnet+sam3d+ground 四步占 87% 总耗时，降低到 <50min。*（来源：WAS8wadJ 方案文档 + C6l2w9Yb 预处理调研）*
- **报错规范化**：周蔚旭整理报错信息、与开拓排期改进呈现方式。
- **Difix 变道效果优化**：构造 <feedforward 新视角渲染、GT 新视角监督、原车道 Ref 图> 训练 pair，改善变道后 ref 图偏差导致的渲染质量下降，预期 5.30。*（来源：WAS8wadJ 方案文档）*
- **持续迭代**：周二 WM 会常态化收反馈、迭代；推广仿真设置自适应。
- **一键链路自动化**：用户拿到高优复现 case 后可一键运行，自动完成数据集构建→预处理→仿真运行（排期待定）。*（来源：WAS8wadJ 方案文档）*
