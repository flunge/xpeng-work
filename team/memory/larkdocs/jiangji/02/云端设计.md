# 阶段一 · 云端设计（现有微信云）

> 阶段一云端 = 微信云开发（运营侧，已实现）+ 设备目录/绑定雏形。计时数据云（过线入库/认人路由/AI 分析）是量产重点（见"阶段二"目录）。

## 一、两条云端职责（勿混）

| 云 | 承载 | 触发 | 阶段 |
|-|-|-|-|
| **微信云开发** | 运营：预约/课程/课卡/订单/用户/教练/学员/打榜/设备目录 | 小程序调用 | 阶段一（现有） |
| **腾讯云 COS+云函数** | 骑行数据：过线入库、认人路由、圈速/遥测、AI 分析 | 基站 4G → COS 事件 → 云函数 | 阶段二（规划） |

## 二、运营云函数（微信云开发，现有）

单入口按事件类型路由到各服务模块，返回统一格式 `{success, data}`：

| 域 | 服务 |
|-|-|
| 认证/角色 | auth, user, member, child |
| 约课/排班 | schedule, availability, booking, reservation, course |
| 课卡/消费/订单 | card, consume, order, purchase |
| 门店/城市/公开数据 | store, city, publicData |
| 教练 | coach |
| 邀请/打榜/课评/直播 | invite, ranking, review, live |
| 通知/训练/种子 | notify, training, seed |
| **设备** | device（查我的设备 / 购买 / 激活 / 记录标定） |

## 三、设备目录数据（现有）

```
devices ( id, 车主手机, openid, 产品ID, 产品名, 价格,
          管理密钥(唯一), BLE名, 状态(未激活/激活),
          购买时间, 绑定时间, 最近标定时间 )
```

> 现阶段设备**目录/绑定在微信云；过线数据入库/路由/签到**尚未落地——那是阶段二计时数据云的内容。

## 四、返回格式约定

云函数返回统一 `{ success:true, data:{...} }` 或 `{ success:false, errMsg:'...' }`。数据库集合/字段变更须先列清单、人工在云控制台操作后再依赖。
