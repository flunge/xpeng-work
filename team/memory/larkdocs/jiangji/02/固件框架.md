> 两个固件、一条 2.4G 链路。阶段一已实现的任务编排、数据流、契约。

## 一、总览

```
车载标签 (ESP32-S3)                    过线基站 (ESP32-S3 + 4G)
├ IMU 1kHz → 融合(VQF+ESKF) → odom     ├ ESP-NOW 收全场标签的包
├ LF 唤醒中断 → 锁微秒时间戳(计时核心)   ├ 组 JSON
├ 腾空检测(0g)                          ├ 上云（阶段一 WiFi 调试）
├ BLE(标定/看姿态/绑定/触发调试)         └ （4G/断网补传见阶段二）
└ ESP-NOW 上行 odom ──────2.4G────────►
```

**三条铁律**：

- **计时**：时间戳在标签的 LF 唤醒中断里锁存（微秒），发送异步；不用基站收包时刻（跨基站也天然可减，同一标签时钟）；
- **边缘解算只传 odom 状态量**（姿态/腾空/速度），不传原始 IMU（原始留 flash 供事后云端 RTS）；
- **中断只锁时间戳 + 入队**，采集/解算/发送都在任务。

## 二、车载标签固件

**任务编排**：

| 任务 | 频率 | 职责 |
|-|-|-|
| imu_task | \~500Hz（实测） | 读 IMU → 融合管线（标定→初始化→ESKF/VQF）→ 更新 odom；**用实测 dt** |
| lf_task | 事件（唤醒中断） | 过线：中断锁微秒戳 → 任务读 RSSI + 标记过线 + 锚点重置 |
| baro_task | \~25Hz | 气压高度 → ESKF 高度约束（大 R，仅压趋势） |
| uplink_task | 事件+1Hz 心跳 | 组 odom 包 → ESP-NOW 发基站 |
| console/ble | 低频 | 串口标定 / BLE 服务 |

**关键设计点**：

- **dt 用实测值**：循环非精确 1kHz（约 2ms/500Hz），固定 1ms 会让姿态半速旋转（已修 bug），用两帧时间差夹逼；
- **姿态前端 = VQF**：VQF 6 轴出姿态注入 ESKF 名义姿态，ESKF 保留速度/位置/气压/锚点；
- **标定**：陀螺静态 + 加计六面 → 落 NVS，开机自动加载；
- **飞行记录器**：原始 IMU 100Hz + 气压 + 解算 + LF 触发 → 日志文件，BLE 拉取。

## 三、过线基站固件

**职责**：ESP-NOW 收全场标签 odom → 组 JSON → 上云。圈速在云端算（用标签时间戳）。

**阶段一联调加固**（对应"端到端有数据""可复现"验收）：

1. **可观测**：per-tag 统计 收/去重/丢包，由序号缺口估丢包率，定期打印 → 收发对得上账；
2. **多标签不串味**：per-tag 序号去重，重复/乱序包丢弃只上传新包；处理 32 位回绕；
3. **上云不裸奔**：验 TLS 证书 + 设备鉴权头（云函数须校验）；
4. **无硬件可验**：主机孪生测试（去重/统计/JSON，全通过）纳入护城河。

## 四、跨边界契约（改动须同步对端 + 升版本）

| 契约 | 对端 |
|-|-|
| BLE GATT 协议 | 小程序 |
| ESP-NOW odom 包结构 | 基站 |
| 标定 NVS 序列化 | 已烧录设备 |
| OTA 线协议 | 基站↔标签 |
| 固件版本号 | 小程序/OTA |

## 五、分层架构

L0 线性代数 → L1 驱动(IMU/LF/气压/链路) → L2 估计(ESKF/标定/初始化/VQF) → L3 服务(BLE/日志/OTA) → L4 编排(标签/基站主程序)。依赖只能自上而下。

> **旁路**：无源计时基站是独立并存的第二种基站（不走 ESP-NOW，改由光电中断+RFID+4G），见"阶段 1.5"目录。相关：**方案总览**、算法细节见"核心算法"目录。
