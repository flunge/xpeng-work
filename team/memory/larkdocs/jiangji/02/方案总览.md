# 阶段一 · 调试验证方案总览

> 目标：用现成模块搭临时设备，**把整条链路走通**——不追求量产，先能用 > 完美。计时用中科微 CSM 的 125kHz LF 方案（激励器 + Si3933）。

## 一、交付目标

| 项 | 阶段一要做到 |
|-|-|
| 计时触发 | 车经过起点/终点被 125kHz 唤醒，车端打**微秒时间戳** |
| 骑行数据 | 车端 6 轴 IMU → 姿态/过弯倾角/腾空（边缘解算，输出状态量） |
| 无线链路 | 车端 **ESP-NOW** 把 {id, 时刻, 运动状态} 发给赛道基站 |
| 云端 | 基站 WiFi 上云（腾讯云），算成绩 |
| 小程序 | 绑定 + 看圈速/成绩 + 骑行曲线（最小可视化） |
| **验收** | 一名骑手过起→终点，小程序**秒级**显示成绩 + 一段骑行数据 |

> 单点位亦可起步（先验证"唤醒→打时间戳→上云→展示"），跑通后再加第二点位做起点+终点。

## 二、系统架构

```
┌ 赛道侧过线点 ─────────────┐
│ CSM 125K 激励器（发125kHz）│  起点/终点各一（先一个）
└──────────┬────────────────┘
  125kHz 唤醒 ▼
┌ 车载终端（面包板，绑车上）──────────┐
│ ESP32-S3-DevKitC-1                    │
│ + Si3933（LF唤醒，WAKE→中断打微秒戳） │
│ + GY-91（MPU9250+BMP280，I2C）        │
│ · 读 IMU → 姿态 + 腾空检测            │
│ · ESP-NOW 发 {id, 时刻, 状态}         │
└──────────┬────────────────────────────┘
  2.4G ESP-NOW ▼
┌ 赛道基站（第二块 DevKitC）┐
│ 收 ESP-NOW → WiFi 上云    │
└──────────┬────────────────┘
  HTTPS ▼
┌ 腾讯云：云函数 ID路由/算成绩/数据库 ┐
└──────────┬──────────────────────────┘
           ▼ 微信小程序：绑定/成绩/骑行曲线
```

**计时互通要点**：激励器与 Si3933 同为中科微，125kHz ASK + 32 位曼彻斯特，配套 sample 代码互通最稳；起/终点用**不同唤醒码**区分。

## 三、实施步骤（建议顺序）

1. **子系统 A 单机**（桌面）：DevKitC + GY-91 → 读 IMU + 姿态 + 腾空，串口打印；
2. **计时唤醒**：接 Si3933 + CSM 激励器 → 验证"过区被唤醒 + 打微秒时间戳 + 读激励器 ID"；
3. **ESP-NOW 两节点**：车端→基站收发 {id, 时刻, 状态} 跑通；
4. **上云**：基站 WiFi → 云函数写库 → 数据库能看到记录；
5. **小程序**：拉库显示成绩 + 一条曲线；
6. **上车场地测**：充电宝供电 + 扎带固定，慢骑→提速，验证唤醒可靠性 + 数据连续；
7. **加第二点位**：起点+终点不同码，验证"出发/到达"成绩。

## 四、验收标准（链路走通 = 阶段一完成）

- ✅ 车经过激励器区**可靠被唤醒**（多次、提速下不漏）；
- ✅ 车端打出**微秒时间戳** + 正确的**激励器 ID**（区分起/终）；
- ✅ IMU **姿态/腾空/倾角**解算合理（与动作对得上）；
- ✅ ESP-NOW → 基站 → 云**端到端有数据**；
- ✅ 小程序**秒级显示**成绩 + 一段骑行曲线。

## 五、风险与对策

| 风险 | 对策 |
|-|-|
| 激励器是周期广播（找物模式），唤不到快速过线的车 | 上位机设连续/高频发射；确认占空比/续航 |
| 唤醒区太宽，过线点不准 | 调短激活距离/降功率；阶段一先求"能唤醒+能打戳"，精度后续优化 |
| 面包板震动掉线 | 扎带/EVA 固定 + 关键线焊接；先慢骑验证 |
| Si3933 寄存器/唤醒码配置 | 用 CSM sample 移植；先频率检测、后唤醒向量 |
| IMU 速度/位置积分漂移 | 阶段一只要姿态/腾空/倾角（可靠）；速度用两点距离/时间，位置不追求 |

> 阶段一只为"走通"，精度、防水、量产留到阶段二。相关（见同目录）：**硬件接线**、**固件框架**、**云端**、**小程序**、子目录**开发环境与烧录**。
