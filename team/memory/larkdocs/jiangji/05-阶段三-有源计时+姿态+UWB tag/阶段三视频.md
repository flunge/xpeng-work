# 阶段三　视频系统：IPcamera + NVR + 视频剪辑 + 自动触发 + 网络互联

> **目标**：在计时/数据系统之上，加**自动高光视频**——摄像头连续录，按计时/IMU 事件**自动剪辑**出每位骑手的高光片段，打通到小程序。  
> 前置：阶段二车载/地面站量产，事件（带 UTC 时间戳）稳定产出。

---

## 一、范围与交付

- IP 摄像机架设（跳跃区/终点，多机位可选）+ NVR/边缘盒录像；
- **事件驱动自动剪辑**：按"骑手 ID + 起跳/最佳圈 + UTC 时间戳"裁片；
- 网络互联：相机—边缘盒—基站—云—小程序打通；
- 交付：自动生成每人高光短片（可数据叠加），小程序可看/分享。

---

## 二、核心做法（连续录 + 时间戳裁剪）

**摄像头 24/7（开放时段）连续录，事件只作"事后裁剪的时间标记"——不触发相机启停（会漏起跳前过程），只需 NTP 对齐两条时间轴**。

```
IP相机(开放时段连续录, RTSP) ──► 边缘盒(NVR/mini-PC, 本地全程录像)
基站ESP32 ──{骑手ID, 事件, UTC时间戳}(NTP对齐)──► 边缘盒
边缘盒: ffmpeg 按时间戳裁 [起跳-2s, 落地+2s] (+可选GPU: 防抖/auto-reframe/慢放/数据叠加)
   └─ 只上传短片 ──► 腾讯云 COS ──► DB(绑 user_id) ──► 小程序 拉取/播放/分享
```

- **身份**：同一时刻区内只一人，靠时间戳唯一对应，**无需人脸识别**。
- **精彩选片**：靠**我方 IMU 指标**（最高跳/最快圈）排序，不依赖视频 AI。

## 四、软件 / 算法

- **录像/裁剪**：RTSP 拉流 + 连续录(分段文件)；ffmpeg 按 UTC 时间戳精确裁片。
- **AI 辅助（可选，边缘 GPU 或云）：视频防抖、目标跟踪/auto-reframe（把骑手框住自动构图）、慢动作（高帧率切慢放）、数据叠加**（腾空高度/速度/成绩 overlay）；集锦模板拼接 + 音乐字幕。
- **时间同步**：相机与基站同一 NTP 服务器；必要时一次性视觉对时（闪光/二维码）。
- **网络互联**：相机/边缘盒局域网；基站事件经 MQTT/HTTP 给边缘盒；边缘盒只上传短片到云。

---

## 五、云端 + 小程序

- 短片存 COS → DB 记录 `{user_id, 片段URL, 指标, 时间}`（与 telemetry 同构，复用 user_id 路由）；
- 小程序：高光列表、播放、下载、分享；与成绩/数据页打通。
- 重的视频 AI 可放云端 GPU / 腾讯云 VOD-MPS（转码/标签）；但**全程视频上云带宽贵**，推荐裁剪留边缘、云端只处理短片。

## 七、风险

- 监控相机"监控味"，家长嫌不好看 → 高帧率+紧构图+AI 美化+数据叠加；精品角度加运动相机。
- 时间同步偏差 → NTP + 视觉对时；裁片留 ±2s 余量。
- 全程视频带宽/存储 → 裁剪留边缘、只上短片；开放时段录像而非 24/7。
