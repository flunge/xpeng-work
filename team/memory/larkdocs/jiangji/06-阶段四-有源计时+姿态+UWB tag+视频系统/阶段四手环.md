# 阶段四　手环模组：6轴IMU + 人体数据，四端互联，与车端并存做发力分析

> **目标**：新增**手环设备**（6 轴 IMU + 人体数据：心率/体温），打通**四端互联（手环 + 车端 + 基站 + 云端）；手环与车端并存**——车端测车身动态、手环测人体，二者融合**分析选手发力**。  
> 前置：阶段二车载量产、阶段三视频/数据链成形。

---

## 一、范围与交付

- 手环硬件（6 轴 IMU + PPG 心率 + 体温 + 计时唤醒 + 2.4G）；
- 贴肤防水表壳（公模套壳，PPG 透光窗/金属体温片/磁吸充电）；
- **四端互联**：手环 ↔ 基站(2.4G/ESP-NOW) ↔ 云 ↔ 小程序；手环与车端各自上行，云端按 user_id + 时间融合；
- **发力分析**：车身动态(车端) + 人体姿态/心率(手环) 融合，输出蹬踏/压泵发力、左右平衡、节奏、负荷等。

## 三、四端互联架构

```
[手环] ESP32-S3 + IMU + PPG/体温 ──ESP-NOW──┐
                                            ├─► [基站 ESP32] ──WiFi/4G──► [云端] ──► [小程序]
[车端] ESP32-S3 + IMU(+Si3933计时) ─ESP-NOW─┘
   云端按 user_id + UTC 时间戳 融合 车端(车身) + 手环(人体) 两路数据
```

- 手环与车端**并存**：各自唯一 ID、各自上行；云端时间对齐后融合。
- 计时仍由车端(或手环)LF 唤醒打戳；手环主打**人体数据 + 签到入场(LF/NFC)**。

---

## 四、算法：发力分析（核心价值）

- **数据源**：车端 IMU(车身姿态/加速度/腾空/压泵) + 手环 IMU(肢体动作/姿态) + 手环心率(强度/负荷)。
- **发力指标**：压泵/蹬踏发力节奏与幅度、出弯发力、左右/前后平衡、动作流畅度/一致性、单位心率的输出（效率）、疲劳(HRV)。
- **方法**：车端与手环 IMU 时间对齐 → 关节/车体运动学关联；心率区间 + HRV 算负荷；规则/统计 + 可选轻量模型；云端 LLM 生成教练点评。
- **位置**：实时姿态/心率边缘解算（端）；发力融合分析、热力图、报告、对比 → **云端**。

## 六、风险

- 腕部运动心率难（运动伪迹）→ 绿光 MAX30101 + IMU 融合；血氧仅静息可信。
- 贴肤结构(光学窗/导热/防水)→ 用公模套壳，避免自研开模。
- 双设备佩戴体验 → 手环轻量化；车端+手环数据云端融合不增加用户操作。
- 四端时间对齐 → 统一 UTC/对时信标。
