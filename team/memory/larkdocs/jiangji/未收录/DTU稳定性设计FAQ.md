# DTU稳定性设计FAQ

> 来源: https://yinerda.yuque.com/yt1fh6/4gdtu/wuvitdrh41quiume  
> 路径: DTU产品FAQ > DTU稳定性设计FAQ

系统稳定是说的客户的的整个系统，不只是DTU。包含客户设备、4G 模块、服务器。在这个过程中，4G模块与银尔达有关，银尔达致力于提供方便，快捷，稳定的联网方案。本文讲解配合4G模块如何设计稳定的系统。

# 一、硬件相关

## 1.1、供电稳定

对于4G模块来讲，不管外部是什么电压，内部都转换成共地电压是3.8V ，最大2A电流，7.6W左右；我们建议非电池电源功率足够10W左右，这个和平均功耗无关。电源需要提供最大的瞬间供电能力否则可能模块会死机。3.3\~4.2V 供电，需要提供最大电流2A能力，最低电压建议3.5V，3.3V比较极限文波会影响。5\~36V 供电，功率10W左右，5V 2A，12V 1A，24V 0.5A，要预留余量，特别是高低温环境下电源性能可能减弱。3.6V 锂亚电池供电，需要加电容，提高电池瞬间供电能力。实际使用的时候要预留自己设备的本身功耗和4G模块的功耗。

案例一：有客户用12V 1A的电源，要带12路继电器+12路数码管+喇叭+4G模块，这个12V 1A电源模块就够呛满足不了极限需求，导致4G模块不稳定。

案例二：有客户使用220V转5V电源给模块供电，但是由于5V比较极限，加上电源文波大于300mv,使电源跌落到4.7V以下了，导致4G模块不稳定，这种推荐12V电源供电。

案例三：3.3V\~4.2V供电的设备供电注意事项:如M780-C，要考虑电源文波问题，一般要推荐3.5V以上供电，典型电压是3.8V。如果用3.3V供电，对电源文波要求很高，不能超过50mv,要不然机会跌落低于3.3V导致模块工作不稳定 。

如果供电主机提供的供电能力不能满足，比如主机智能提供5V 300ma，怎么办?可以并联多电容、超级电容、或者电池，加大瞬间供电能力，这些设计可以做到自己的主机里面，如果主机固定了，可以定制做到4G模块里面。

## 1.2、电源可控或者复位脚

对于有MCU+4G模块的场景，如果MCU能够控制4G模块的电源或者复位脚，就尽量引出控制，当4G模块异常的时候(串口数据不通，连不上网，收不到服务器数据)，就控制4G模块重启，重启重新初始化，基本能解决99.99%的问题。前提自己的MCU稳定可靠。

有的场景无法控制模块的电源和复位，这种就必须依托在4G 模块自身稳定性上面，Air724系列内部有看门狗（2020年开始产品验证，绝大部分稳定可靠）；Air780系列除核心板系列外，基本都有外部看门狗，能最大程度保证硬件稳定，但是也不能完全避免异常。

## 1.3、天线安装

天线安装不能放在密闭的金属里面。天线信号质量要大于17比较好。特殊场景需要匹配天线，达到最好的效果。

# 二、业务逻辑设计相关

在业务设计通讯设计上，要注意。DTU可以自己维护网络尽量尝试恢复网络，AT固件必须自己做逻辑维护网络，恢复网络。

建议设计业务心跳逻辑去确认设备和网络是否正常。比如设备周期2分钟给服务器发数据，服务器应答数据。只要任何一方超过3次没收到任何数据，就可以认为对方异常了，触发设备维护逻辑。这种方法行之有效。不管是TCP，MQTT，UDP，HTTP 或者其他第三方平台云，都可以按这个方法做。个人觉得MQTT用遗嘱这些不是最靠谱的。使用业务心跳，平常有数据通讯的时候就不发，无数据的时候就发约定的心跳数据，频率越快，延迟越小，流量消耗越多（不过现在流量很便宜，基本客户忽略）。

平时正常业务交互的时候，也要设计成一问一答的形式，如果发数据后，最长2-3秒等待超时，超时后重发，如果多次都收不到应答就表示异常了，做异常处理逻辑。

有的系统无法设计业务心跳，只有设备单方面上报数据，服务器不应答设备，服务器偶尔主动下发数据，这种场景可以设置DTU的自动重启时间，DTU串口无数据重启时间，DTU网络无数据重启时间来尽量能自动恢复异常。

# 三、SIM卡相关

SIM卡要正规渠道购买。SIM卡流量要评估准确，否则会流量超标，导致停机。SIM卡需要记录ICCID，方便SIM卡续费。建议传到自己的服务器记录设备和ICCID的关系，方便续费管理，和手机卡一样，如果不续费SIM卡会销号，导致必须本地更换SIM卡，如果是贴片卡还必须返厂焊接，会产生巨大售后问题。建议提前2个月开始续费，建议在月初续费，避免在月底续费。

很多客户系统设计没记录SIM卡ICCID导致问题，如果DTU固件，用的是WEB 配置，系统会自动记录SIM卡ICCID，用户可以省去这个步骤。

# 四、关于服务器相关

对于少量设备对接，可以自己搭建设备管理服务器，节约成本。如果对于设备量多的，建议用第三方设备接入服务器，就不用过多考虑稳定性问题了，当然成本也高。

业务上面尽量设计第二点的业务心跳逻辑，做到设备，4G模块，服务器，业务4方确认，绝对没错。
