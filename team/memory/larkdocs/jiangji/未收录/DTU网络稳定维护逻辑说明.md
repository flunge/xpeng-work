# DTU网络稳定维护逻辑说明

> 来源: https://yinerda.yuque.com/yt1fh6/4gdtu/dkfpzb4f4gt9k92u  
> 路径: DTU通用入门教程 > DTU网络稳定维护逻辑说明

# 一、硬件维护

添加外部独立看门狗，防止设备死机。

# 二、软件维护

如何保证设备正常运行，DTU/RTU策略是网络优先。如果连不上目标服务器，会自动重连重启。

1、上电检查SIM卡是否不识别

如果检查到SIM不识别，LED提示指示，5分钟后重启设备

2、上电检查SIM卡是否能注册网络

上电5分钟注册不了网络(链接不是基站)，设备重启

3、链接服务器维护逻辑

在网络正常情况下，设备连续20次(100秒)链接不上目标服务器，或者接收数据、发送数据异常后设备重启。接收异常和发送异常后，自动断开链接，然后重新链接进服务器。

4、多个通道链接网络维护逻辑

当有多个通道链接时，只要其中某一个通道断开，都会执行网络维护逻辑当有多个通道链接时，只要其中某一个通道断开，都会执行网络维护逻辑

# 三、参数维护

有三个自动重启逻辑，设备定时重启，设备无网络数据重启，设备无串口数据重启逻辑进一步维护网络稳定性。

# 四、通信协议维护

主要是周期的心跳包，或者周期的业务交互数据。

# 五、带来的一些问题

如果DTU需要离网储存数据或者输入计数等逻辑就会受到影响。因为设备是网络异常后会重启，会导致在边缘计算的时候，内存数据丢失，然后再重启的时候不能处理外部数据。

这些需要根据自己的场景评估，要做这些逻辑一般可以外部扩展485设备，或者定制固件逻辑，做不重启逻辑。
