# 编译预检清单（阶段一）

> 装好 ESP-IDF ≥ 5.4 后，按此清单逐项过关。tag 和 base 是**两套独立工程**，分别构建。  
> **开发环境：VS Code + 官方「Espressif IDF」扩展（不要用 PlatformIO，避免两套混用）。Windows 为主调试系统（编译/烧录/调试都在 Windows），Mac 备用。编译不需要任何硬件**，只有「烧录/监视」才需插板子。  
> 👉 Windows 完整流程（装环境 + 编译 + 烧录）见 **`Windows-setup-and-flashing.md`**（主文档）。

---

## 0. 环境准备（VS Code 扩展方式，推荐）

### 0.1 装扩展（Mac / Windows 通用）

1. VS Code → 扩展市场搜 **「Espressif IDF」**（作者 Espressif Systems）→ Install。
2. 命令面板（Mac `⌘⇧P` / Win `Ctrl+Shift+P`）→ **`ESP-IDF: Configure ESP-IDF Extension`**。
3. 选 **EXPRESS** 安装 → 版本选 **v5.4 (release)** → 工具链/Python 让它自动下载装好（约 1.5GB，一次到位）。

   - Mac 装到 `~/esp/` + `~/.espressif/`；Windows 装到 `%USERPROFILE%\esp\` + `%USERPROFILE%\.espressif\`。
4. 装完底栏出现 ESP-IDF 工具条（🔌端口、⚙️芯片、🔨build、⚡flash、🖥monitor、🔥「build+flash+monitor」一键）。

### 0.2 打开工程（tag / base 各开一个窗口）

- tag 和 base 是**两个独立 IDF 工程**，**必须各自单独「打开文件夹」**：

  - Mac：`File → Open Folder → firmware/tag`（另开一窗 `firmware/base`）。
  - ⚠️ 不要直接打开 `firmware/` 根目录——扩展找不到顶层 `CMakeLists.txt` 会报错。
- 底栏 ⚙️ 选目标芯片 **esp32s3**（tag、base 各设一次）。

### 0.3 编译（GUI 或命令行二选一）

- **GUI**：底栏点 🔨（`ESP-IDF: Build your project`）。首次会自动套用 `sdkconfig.defaults` 生成 `sdkconfig`。
- **命令行**（扩展也内置终端，命令面板 `ESP-IDF: Open ESP-IDF Terminal` 进，环境已激活）：

  ```bash
  idf.py set-target esp32s3   # 仅首次
  idf.py build
  ```

### 0.4 纯命令行装法（不想用扩展时备选）

```bash
# Mac
git clone --recursive -b v5.4 https://github.com/espressif/esp-idf.git ~/esp/esp-idf
~/esp/esp-idf/install.sh esp32s3
. ~/esp/esp-idf/export.sh        # 每个新终端都要 source
# Windows 用 install.bat / export.bat（建议在「ESP-IDF 5.4 PowerShell」里跑）
```

### 0.5 验收

- `idf.py --version` ≥ 5.4；底栏芯片显示 esp32s3。
- **本工程已预置**：`sdkconfig.defaults`（tag 含 BLE/coex、base 含 HTTPS）+ tag 的 `partitions.csv`，首次 build 自动套用，无需手动 menuconfig。

## 1. base 基站（纯 C，最简单，先过）

```bash
cd firmware/base
idf.py set-target esp32s3
idf.py build
```

### 预期问题 & 解法

| # | 问题 | 原因 | 解法 |
|-|-|-|-|
| B1 | `espnow_link.h` not found | base 需要 link 组件的头文件 | 在 `base/CMakeLists.txt` 加 `set(EXTRA_COMPONENT_DIRS ../components)` |
| B2 | `odom_packet_t` 未定义 | 同上 | B1 解决即可 |
| B3 | `cloud.h` / `cloud_wifi.c` 编译错误 | esp_http_client 未链接 | `base/main/CMakeLists.txt` REQUIRES 加 `esp_http_client` |
| B4 | WiFi 信道 vs AP 冲突（运行时） | `esp_wifi_set_channel` 在已连 AP 后无效 | 阶段一让 AP 固定信道=ESPNOW_CHANNEL；或 base 不连 AP(纯 ESP-NOW+串口打印) |

### menuconfig 关注项

- `Component config → ESP-NOW → Enable ESP-NOW`（确认打开）
- `Component config → ESP-TLS → 允许 HTTPS`（cloud_wifi 用到 esp_http_client）

> 📋 实际首次编译时 base 遇到的真实错误（含 esp_now 组件消失、uint32_t 格式符、ble_calib 误入等）及修复详见 ESP32-first-build-troubleshooting.md。

## 2. tag 车载标签（C++17，复杂一点）

```bash
cd firmware/tag
idf.py set-target esp32s3
idf.py build
```

### 预期问题 & 解法

| # | 问题 | 原因 | 解法 |
|-|-|-|-|
| T1 | C++17 标志未生效 | `set_source_files_properties(... COMPILE_OPTIONS "-std=gnu++17")` 可能不够 | 已在各 C++ 组件 CMakeLists 设；若仍报错，`tag/main/CMakeLists.txt` 追加 `idf_component_register(... COMPILE_OPTIONS "-std=gnu++17")` |
| T2 | NimBLE 头文件缺失 | BLE 未启用 | ✅ **已预置**`sdkconfig.defaults`：`CONFIG_BT_ENABLED`+`CONFIG_BT_NIMBLE_ENABLED`。若改了 sdkconfig 丢失，重新 build 会自动套用 defaults |
| T3 | `nimble/nimble_port.h` 找不到 | REQUIRES 缺 `bt` | ✅ 已在 `ble_calib/CMakeLists.txt` REQUIRES 含 `bt` |
| T4 | `#include "bmp280.h"` 找不到 | baro 组件未注册 | ✅ 已有 `components/baro/CMakeLists.txt` |
| T5 | `spi_device_handle_t` / `i2c_port_t` 未定义 | REQUIRES 缺 `driver` | ✅ imu/si3933/baro 均已含 `driver` |
| T6 | `nvs_flash.h` 找不到 | REQUIRES 缺 `nvs_flash` | ✅ tag/main 已含；calib 用 `PRIV_REQUIRES nvs_flash` |
| T7 | 固件塞不进分区 | 默认 1MB app 分区放不下 WiFi+BLE+ESKF | ✅ **已预置**`partitions.csv`（3MB×2 OTA）+ sdkconfig 指向它 |
| T8 | WiFi/BLE 同跑互相踩（运行时） | 单天线未开共存 | ✅ **已预置**`CONFIG_ESP_COEX_SW_COEXIST_ENABLE` |
| T9 | 栈不够 crash（运行时） | ESKF 15×15 矩阵在栈上 \~4KB | imu_task 栈已设 8192；若仍不够提到 12288 |
| T10 | Si3933 寄存器值不对（运行时） | 3 个 TODO 未填 | 对照 datasheet/示波器确认 R0_pattern_len、R16 谐振频率、payload 寄存器地址 |

### sdkconfig 已预置项（无需手动 menuconfig）

本工程 `firmware/tag/sdkconfig.defaults` 已写入，首次 build 自动生效：

- 蓝牙：`CONFIG_BT_ENABLED` / `CONFIG_BT_NIMBLE_ENABLED`（仅 peripheral+broadcaster）
- 共存：`CONFIG_ESP_COEX_SW_COEXIST_ENABLE`（WiFi(ESP-NOW)+BLE 单天线必须）
- 分区：`CONFIG_PARTITION_TABLE_CUSTOM` → `partitions.csv`
- 主频：`CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240` / `CONFIG_FREERTOS_HZ=1000`

> 若想图形化核对：底栏 ⚙️ 或命令面板 `ESP-IDF: SDK Configuration Editor (menuconfig)`。

> 📋 实际首次编译时 tag 遇到的真实错误（GCC14 cstdlib 冲突、UUID 双括号、BLE_TOKEN_LEN 不可见等）及修复详见 ESP32-first-build-troubleshooting.md。

## 3. 两工程共享 components 的 CMake 布局

```
firmware/
├── tag/CMakeLists.txt          ← 顶层，含 set(EXTRA_COMPONENT_DIRS ../components)
├── base/CMakeLists.txt         ← 顶层，含 set(EXTRA_COMPONENT_DIRS ../components)
└── components/
    ├── estimator/CMakeLists.txt   (header-only: SRCS 为空, INCLUDE_DIRS "include")
    ├── calib/CMakeLists.txt       (SRCS: calib_store.cpp  REQUIRES: nvs_flash)
    ├── init/CMakeLists.txt        (SRCS: init_static.cpp)
    ├── ble_calib/CMakeLists.txt   (SRCS: ble_calib_svc.cpp  REQUIRES: bt nvs_flash)
    ├── baro/CMakeLists.txt        (SRCS: bmp280.c  REQUIRES: driver)
    ├── imu/CMakeLists.txt         (REQUIRES: driver)
    ├── si3933/CMakeLists.txt      (REQUIRES: driver esp_timer)
    ├── link/CMakeLists.txt        (REQUIRES: esp_wifi esp_now)
    └── fusion/CMakeLists.txt      (header-only 或 .cpp)
```

> 若 `set(EXTRA_COMPONENT_DIRS ...)` 写在顶层 CMakeLists 的 `project()`**之前**才生效。

## 4. 推荐构建顺序（纯编译，无需硬件）

1. **base** — 纯 C，依赖少，最先过 → 确认共享 components 链路通
2. **tag** — C++17 + BLE + 多传感器，BLE/分区/共存已在 sdkconfig 预置，直接 build
3. 两个都 `idf.py build` 成功（终端出现 `Project build complete` + `.bin` 大小）即达成「编译落地」目标，**到此不需要任何硬件**。
4. （硬件到货后）**烧录 base** → 串口打印 MAC → 填回 tag 的 `BASE_MAC`
5. （硬件到货后）**烧录 tag** → 串口看 IMU 初始化 → 静止对齐 → RUNNING

## 4b. 烧录 & 监视（VS Code，硬件到货后）

| 动作 | VS Code | 命令行 |
|-|-|-|
| 选串口 | 底栏 🔌（`ESP-IDF: Select Port`） | `idf.py -p <PORT>` |
| 烧录 | 底栏 ⚡（`Flash`），首次选 **UART** 烧录方式 | `idf.py -p <PORT> flash` |
| 串口监视 | 底栏 🖥（`Monitor`） | `idf.py -p <PORT> monitor` |
| 一键 build+flash+monitor | 底栏 🔥（火焰图标） | `idf.py -p <PORT> flash monitor` |

**串口名**：

- **Mac**：`/dev/cu.usbserial-*` 或 `/dev/cu.usbmodem*`（DevKitC-1 的 USB 口）。装不上看到口 → 装 CP210x/CH34x 驱动。
- **Windows**：设备管理器里的 `COMx`。
- 退出 monitor：`Ctrl+]`。

## 5. 真机调试检查点

| 检查点 | 预期 | 排查 |
|-|-|-|
| IMU WHO_AM_I | 串口打印 `0x44`(ICM-42686) 或 `0x47`(ICM-42688) | SPI 接线/CS/时钟极性 |
| 静止初始化 | \~200ms 后打印 `INIT→RUNNING` | 放平不动；threshold 偏紧可放宽 |
| BMP280 chip_id | 读出 `0x58` | I2C 地址 0x76(SDO→GND) 或 0x77(SDO→VCC) |
| Si3933 唤醒 | 激励器通电后 WAKE 脚拉高 + 串口打印 pattern | R0/R16 寄存器；天线谐振 |
| ESP-NOW 到 base | base 串口 `收 N 上云 M` 递增 | 信道一致；tag BASE_MAC 正确 |
| BLE 广播 | 微信小程序扫到 `tag-calib-01` | sdkconfig 已开 NimBLE；天线/共存 |
| 云端收数 | 腾讯云 SCF 日志有 JSON | WiFi 连通；URL 正确；TLS 证书 |
