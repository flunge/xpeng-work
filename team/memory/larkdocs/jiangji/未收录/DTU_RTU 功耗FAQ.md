# DTU/RTU 功耗FAQ

# 电源要求说明

电源要求与功耗没有必然关系。对于4G产品，我们要求供电电源必须稳定，稳定的意思就是在任何情况下，都能满足设备的最大电能需求。模组的要求是典型电源是 3.8V供电，2A电流，总7.6W以上。

对于3.3\~4.2V电池供电的设备，要求瞬间电流能达到2A左右(电池有2A的保护板)，一般用锂电池都可以，或者专用的DCDC芯片。

对于5-36V 的供电系统，要求电源功率能达到10W，比如5V 2A，12V 1A，24V 0.5A左右，一般用适配器电源或者专门的DCDC芯片。

为什么要10W左右的电源，是要考虑余量和转换效率等，往往在高温或者低温的情况下，电源性能会打折扣，所有10W左右的电源基本会满足需求。

所以，纽扣电池这些基本是不行的，很多普通开发板的DCDC芯片出来的3.3V或者5V电源可能也不行，功率不够。

充电宝，充电器这些供电也不行，因为模块的平均功耗可能很小，会导致充电宝或者充电器认为外部设备不需要电了，从而断开了电源输出，所以测试的时候要用适配器或者电池单独供电。

锂亚电池需要接电容提供瞬间供供电能力。

# 功耗说明

特别注意平均功耗与电源最大功率选择没必然联系，电源最大功率基本是必须大于8W以上。

功耗说的是平均功耗,是单位时间消耗的总共的电能，前提是保证供电电源最大功率足够的情况才能稳定工作。4G模块在信号好不好或者其他情况下，有瞬间脉冲，可达到2A电流，如果电源最大就100ma，就会导致4g 模块死机。然后4g 模块大部分时间可能平均功耗只有4\~30ma左右，发数据的时候也才100\~200ma。

# 功耗评估方法

根据实际使用条件，按上报间隔与服务器通讯，使用仪器捕获捕获3个通讯周期以上基本就能评估正常情况下的平均功耗，当然采集越长越有说服力，这种不考虑设备异常或者信号不好的情况评估。

比如TCP连接，2分钟与服务器通讯异常，服务器应答这个流程，基本连续捕获6分钟就能评估功耗。

比如TCP连接，超低功耗，30分钟周期唤醒一次，然后采集传感器数据，上报服务器，服务器应答，然后自动休眠这个流程，基本连续捕获几次通讯周期即可。

# 功耗评估注意事项

注意功耗评估按实际场景测试评估是靠谱的。但是不能只评估正常情况下功耗，还需要评估异常情况功耗。异常情况比如网络信号不好，一直注册不了网络；比如服务器异常，设备一直连不上或者没应答等。

遇到异常的情况，要提前做好异常恢复逻辑和异常保护逻辑，如设计最多工作多久还不成强制休眠。不能让设备因为异常一直消耗电能

# 普通功耗简单评估方法

大部分使用场景都不需要考虑功耗，但是前提要保证供电最大功率满足需求。有太阳供电充电的情况下，一般保证15天没太阳的情况就可以。纯电池供电的情况下一般是要求功耗越低越好，需要具体评估或者做超低功耗处理。

1、不做低功耗处理，保持服务器连接，不通讯，5V，电流大约30ma。

2、做低功耗处理，保持连接服务器，不通讯，5V，电流大约10ma。

3、通讯的时候功率 5V，电流大约70\~200ma。

4、GPS 的运行时候，单GPS的功耗大约是5V，电流40ma。

5、单个继电器的功耗一般是0.45W，5V 90ma左右。

总结描述是；

4G模块正常工作平均功耗很低，不发送数据约0.15W左右，发送数据平均功耗1W左右，最大瞬间功耗约8W左右。带继电器设备单个继电器功耗0.45W左右，如有2个继电器，继电器功耗约0.9W。其他外设功耗基本可以忽略。

# 常见产品低功耗说明

Air724不支持超低功耗，Air780支持超低功耗。超低功耗一般用在4G模块作为主机，周期唤醒自动采集数据，上报服务器的场景。Air780的超低功耗必须使用任务才能实现。

对于所有设备都需要注意:

1、实际测试，一般通过连续捕获3-5个工作周期，去计算平均功耗，测试时间越久，越准确。

2、功耗与信号和工作时间长短有关系。

3、当网络异常后，需要做一些逻辑处理，确定最长工作多久后休眠，否则会过快消耗。
