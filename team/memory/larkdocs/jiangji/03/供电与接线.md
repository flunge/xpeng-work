# 阶段 1.5 · 供电与接线

> 所有电子件装进一个防水盒，盒内放 **3S LiPo（内置 BMS）**，全负载统一走 **12V 稳压**。光电头+反光板在盒外过线点，只 3 线缆进盒。

## 一、各器件用电

| 器件 | 供电 | 供电方式 | 电流 | 位置 |
|-|-|-|-|-|
| GL6 光电 | 10-30V | 恒 12V | 30mA | 盒外，3 线进盒 |
| 4G DTU | 7-24V | 恒 12V | 0.15A（发射突发 0.5-2A） | 盒内 |
| ESP32-S3 | 5V | 12V→Buck 5V | 0.2-0.5A | 盒内 |
| **UHF RFID 模块** | **3.7-5V** | **走 5V**（勿接 12V！） | 75-196mA @5V | 盒内 |

## 二、供电架构（3S + Buck-Boost 恒 12V）

**为什么用 3S + 统一 12V 稳压**：负载统一走稳压后与电池节数解耦，选更轻更便宜的 3S；3S 放电 9.0–12.6V 会跌破 12V，故用 **Buck-Boost 升降压恒 12V**（高于降压、低于升压）。好处：负载电压恒定 → 光电输出电平固定、光耦限流电阻一次算死、供电干净。

```
3S LiPo(含内置BMS) 11.1V / 9.0–12.6V
   │ XT60 主放电 + 平衡头(充电)
   ▼
节点A（电池输出，常带电）── 1 进 2 出
   ├─► 电量显示模块（开关前，常显）
   └─► 面板总开关 IP67
          │
       [Buck-Boost → 恒 12V/3A]   ← 统一稳压层
          │
       节点B（恒 12V 主母线）── 1 进 3 出
          ├─► GL6 光电（经光耦板）
          ├─► 4G DTU（并 1000µF 吸收发射突发）
          └─► [Buck → 5V/2-3A]
                 │
              5V 节点 ── 1 进 2 出
                 ├─► ESP32-S3
                 └─► RFID 模块（3.7-5V）
```

**三个扇出节点**：节点A（电池）1进2出（电量显示+开关）；节点B（恒12V）1进3出（GL6/4G/Buck-5V）；5V 节点 1进2出（ESP32/RFID）。

- **RFID 走 5V**（3.7-5V 模块，接 12V 会烧）；5V Buck 带 ESP32+RFID 共 \~0.7A，选 5V/2-3A；
- 电池选**内置 BMS 的 3S 电池包**（过充/过放/过流/均衡自带），无需另配 BMS；
- **续航**：负载 \~7W，经稳压 3S 11.1V 平均 \~0.74A → 5000mAh ≈ 5-7h。营业一天建议 ≥5000mAh，或市电常供 + 电池兜底。

## 三、GL6 光电 → ESP32 接线（关键）

GL6 输出 NPN 且 **HIGH≈供电电压(12V)，绝不能直连 ESP32，必须光耦隔离**（不是简单上拉——高电平会主动到 12V）。用 **PC817 光耦模块**：

```
输入侧（GL6 的 12V 逻辑）          输出侧（ESP32 的 3.3V 逻辑）
  GL6 黑(信号) ─► IN               ESP32 3V3 ─► V1  ← 决定输出=3.3V，勿接5V
  GL6 蓝(GND)  ─► 输入侧 G          OUT(集电极点) ─► ESP32 GPIO
                                    输出侧 G ─► ESP32 GND
```

- **V1 必接 3.3V**（输出高电平=V1 电压，接 3.3V 才安全）；
- **保隔离**：跳线帽不短接、两侧地分开（12V 侧浪涌进不了 ESP32）；
- **反相逻辑**：光耦输入通→输出拉低，软件里对齐"过线=哪个电平沿"；
- 拿到实物用万用表按 PC817 四脚（1=LED+ 2=LED- 3=发射极 4=集电极）对端子。

> 光耦 ≠ 继电器：光耦是光隔离、无触点、微秒级传信号；继电器是磁隔离、机械触点、毫秒级——继电器延迟会毁计时，必须用光耦。

## 四、接插件（几进几出）

**电源端**：节点A「1进2出」+ 节点B「1进3出」12V母线 + 5V「1进2出」+ 电池 XT60/平衡头 JST-XH 4P/充电航插各 1。  
**信号端**：GL6 信号 3P（经格兰头）、光耦→ESP32 2P、RFID-UART（TTL 直连免转换）、4G-UART 各 1 组。

- 主机盒：**IP65+ ABS/PC 塑料防水箱**（非金属，防屏蔽无线），航插/格兰头出线；

## 4G DTU 接线修正：成品 DTU 非 TTL（重要）

<callout emoji="💡">
方案选用**银尔达 Air780EPM 成品 DTU（YED-S710 系列）**。实测其接口/供电与"TTL 直连"假设不符，接线必须修正。
</callout>

| 项 | 成品 S710 DTU 实际 | 接线 |
|-|-|-|
| 接口 | RS232(S710Zm) / RS485(S710Ym)，**非 TTL** | ESP32 UART2(3.3V TTL) → **MAX3232(RS232) 或 MAX485(RS485)** → DTU |
| 供电 | 5-36V，**推荐 12V**（非 5V） | DTU 走 **12V 母线**，与 ESP32 分开 |
| 波特率 | 默认 115200（RS232 可到 460800） | ESP32 UART2 设 115200 |
| 命令 | 私有 config 命令 / **WEB 配置** | 优先 WEB 工具配服务器/APN/透传 |

**软件不变**：ESP32 只往 UART2 写 JSON 行、DTU 透传上云——与物理层 TTL/RS232/RS485 无关。只是硬件多一个电平转换芯片 + DTU 供 12V。

### 使用步骤

1. 买对型号：成品 DTU + **透传固件版**（非 AT 版，硬件不可互刷）；插物联网卡；
2. WEB 配置工具设目标服务器(腾讯云 MQTT/TCP)、APN、透传模式；
3. 接线：ESP32 UART2 → MAX3232/485 → DTU；DTU 供 12V；
4. ESP32 侧 cloud_dtu 往 UART2 写 JSON 行即透传上云；
5. 模块固件远程升级需转移归属到合宙 IOT 平台（与我方 base OTA 是两回事）。

### BOM 补充

\+ MAX3232（RS232 DTU）或 MAX485（RS485 DTU）电平转换芯片/模块 ×1（¥2-8）。DTU 从 12V 母线取电（供电树已有 12V）。

## ⚠️ 上节修正：DTU 选定 YED-S710Cm（TTL 版，直连无需转换）

<callout emoji="💡">
已确认型号 **YED-S710Cm**——TTL 版本。**上一节"RS232/RS485 + MAX3232/485 电平转换"不适用于本型号，以本节为准。**
</callout>

| 项 | S710Cm 实际 | 接线 |
|-|-|-|
| 接口 | **TTL 串口，兼容 3.3V/5V 电平** | ESP32 UART2 直连 DTU 的 TTL RX/TX/GND，**无需电平转换** |
| 供电 | 5-36V，**推荐 12V**（TTL 电平与供电无关） | DTU 走 **12V 母线**，只 TTL 三线接 ESP32 |
| 波特率 | 默认 115200（up to 460800） | UART2 设 115200 |

**关键澄清**：TTL 电平和供电电压是两个独立域——DTU 供 12V 电，但 TTL 串口按 3.3V 逻辑和 ESP32 通信（兼容 3.3V/5V）。所以直连可行、**不用 MAX3232/485、不用分压**。BOM 无需电平转换芯片。

其余（透传固件版、WEB 配置、使用步骤）同上一节不变。

## ✅ 最终接线（以本节为准）：ESP32-S3 ↔ 4G DTU（YED-S710Cm，TTL）

前文只说"UART2 直连"，未写具体引脚，且波特率已改。此节给出确定的引脚与参数，覆盖以上所有描述。

### 引脚对接表（ESP32-S3 DevKitC-1 ↔ S710Cm DTU）

| 信号 | ESP32-S3 引脚 | DTU 引脚 | 说明 |
|-|-|-|-|
| ESP32 TX → DTU RX | **GPIO15**（UART2 TX） | DTU **RXD** | ESP32 发，DTU 收 |
| ESP32 RX ← DTU TX | **GPIO16**（UART2 RX） | DTU **TXD** | ESP32 收，DTU 发（**TX↔RX 必须交叉**） |
| 共地 GND | **GND** | DTU **GND** | 必接，逻辑电平基准 |
| DTU 供电 | 不由 ESP32 供 | DTU **VIN=12V** | DTU 从 **12V 母线**取电（非 5V、非 ESP32） |

> 只接 **3 根线（GPIO15、GPIO16、GND）到 DTU 的 TTL 口；DTU 电源另走 12V 母线。TTL 电平 3.3V，S710Cm 兼容 3.3V/5V，直连、不用 MAX3232/485、不分压**。

### 关键参数

- **波特率 = 921600**（已从 115200 提升；ESP32 UART2 与 DTU 两端都要设 921600 才能通信）。
- 数据位 8 / 停止位 1 / 无校验（8N1）。
- 用 **UART2**（UART0 留给 USB 串口日志/烧录；UART1 已被 RFID 模块占用）。
- 引脚以固件 `base-passive/main/pins.h` 为准：`PIN_DTU_TX=GPIO15`、`PIN_DTU_RX=GPIO16`、`DTU_UART=UART_NUM_2`、`DTU_BAUD=921600`；`cloud_dtu.c` 按此初始化。RFID(MA82) 用 UART1(GPIO17/18)，不要混用。

### 易错点

- **TX↔RX 交叉**：ESP32 TX 接 DTU RX、ESP32 RX 接 DTU TX；接错（TX-TX/RX-RX）则完全不通。
- **两端波特率一致**：任一端仍是 115200 会乱码；DTU 侧用 WEB 配置工具改成 921600。
- **共地**：ESP32 与 DTU 必须共 GND，否则 TTL 电平无基准。
- DTU 供 12V、ESP32 供 5V，**电源域分开**，只有 TTL 三线与 GND 相连。
