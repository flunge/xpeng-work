# 云端设计（阶段二 · 计时数据云）

> 量产阶段云端要建的**骑行数据链路**：过线上报入库、认人路由、圈速/遥测、会话切分、签到推送、AI 分析。腾讯云 COS/SCF（决策 D13）。  
> 阶段一现有微信云运营函数见 `../phase1-debug/cloud.md`。数据链路带宽见 `data-link.md`，分析方法见 `cloud-ai-analysis.md`。

---

## 一、数据流

```
基站 4G → COS(raw/{date}/{station}/{ts}.json) → 对象事件 → SCF process-crossing
   → 查 tag_bindings(tag_id→user_id) → 入库 → 推送小程序
```

## 二、数据模型（建议）

```
users        ( user_id PK, open_id, phone, nickname )
tag_bindings ( tag_id PK, user_id, owner_token_hash, status )   ← 路由核心
sessions     ( id, user_id IDX, venue_id, start_ts, end_ts, laps, best_lap_ms )
crossings    ( id, user_id IDX, tag_id, exciter_id, point, ts_us, rssi_peak, session_id )
laps         ( id, user_id IDX, session_id, lap_no, lap_ms, max_roll, air_count )
telemetry    ( id, user_id IDX, session_id, ts_ms, roll,pitch,yaw, vz, air_ms, height_mm )
```

## 三、关键规则

- **认人**：过线包只带 `tag_id`，SCF 查 `tag_bindings` 路由到 `user_id`（未绑→unbound 待认领）。
- **圈速**：`t_finish − t_start`，用 **Tag 端微秒时间戳**相减（多基站也可减，基站无需时钟同步）。
- **去重**：多基站覆盖重叠 → 按 `(tag_id, seq)` 去重。
- **认线**：靠 `exciter_id`（激励器唤醒码），不靠哪个基站。
- **AI 分析**：云端（规则引擎 + 个人基线/群体分位 + LLM 措辞），用**漂移免疫特征**，不依赖绝对位置。详见 `cloud-ai-analysis.md`。

## 四、技术选型

- 接入：COS（对象存储）+ SCF（事件触发云函数）。
- 特征工程：SCF（轻量）或 CVM/容器跑 Python（numpy/scipy）。RTS 双向滤波用 200Hz 原始段。
- 存储：云数据库（lap/feature/session）+ 可选时序库。
- ML/LLM：按需 GPU；LLM（混元/Claude）只把特征表翻译成人话，不做数值判断（防幻觉）。

## 五、待落地清单（让计时业务闭环）

1. **owner_token 云端下发**：`activateDevice` 生成 16B token 存 `tag_bindings`，下发小程序写设备。
2. **tag_id→user_id 路由表**：`tag_bindings` 集合 + SCF 路由（现 `device.js` 只到 adminKey↔ownerPhone）。
3. **⭐ 基站 4G 上云接入**：COS 桶 + SCF `process-crossing`（第一优先级，配合 `cloud_4g.c`）。
4. **sessions 自动切分** + **签到事件推送**（订阅消息/WebSocket）。
5. **exciter_id ↔ 场地点位映射**表。
