# 泵道 UWB RTLS 部署方案（40×60m / 8 锚点 / tag 端实时 3D 定位）

<callout emoji="💡">
目标：在 40×60m 泵道用 8 个固定 UWB 锚点（base-3.0）对移动车载标签（tag-3.0）做双向测距，标签端把 IMU 惯导与逐锚 UWB 距离在 ESKF 里紧耦合，实时输出车手的厘米级 3D 位置（x, y, z）。测距由标签发起，并与既有的 LF 过点触发链路耦合——过起点唤醒开测、过终点回睡，每圈过点还给融合一次绝对位置校正。本文承接《UWB 开源方案调研》《tag-3.0 PCB 设计》《base-3.0 PCB 设计》，是阶段三 UWB 预研的部署与固件分工设计。
</callout>

## 1 场地与锚点布局

泵道有效区约 40×60m（2400㎡），对角线约 72m，超过单颗 DW3000 在 6.5GHz 信道下的稳定视距量程（约 30–60m）。因此不能靠四角覆盖全场：任一车手位置都必须能同时测到至少 3 个几何良好的锚点，才能解算平面位置；要解算高度还需锚点不共面。据此采用周边 8 锚点布局——四角加四条边中点，相邻间距约 30m，全部落在稳定量程内，且锚点连成的凸包完整包住整个骑行区。

```text
   A1 ────── A2 ────── A3
   |                    |
   A8       泵道区        A4      40 m
   |      (车手活动)       |
   A7 ────── A6 ────── A5
             60 m
```

锚点坐标在部署时实测并录入（见第 5 章标定）。布点须遵守以下要点：

- **抬高安装。**锚点架到 3–5m 高（灯杆／立柱／看台边），俯视全场，避开车手身体与坡道起伏的遮挡；对应调研与 base-3.0 中"锚点市电常开、可用 WROOM-1U + 外置增益天线"的设计。
- **凸包兜住赛道。**车手不要骑到 8 锚点围成的多边形之外——凸包外侧几何急剧恶化，精度骤降。
- **打破共面。**若要稳定的 z 高度，让部分锚点高度不同（例如四角与四边中点分两个安装高度），避免所有锚点近似共面导致垂直方向病态。
- **远离金属。**避开金属护栏、集装箱、钢结构，减少多径反射。
- **信道选择。**40×60m 用 ch5（6.5GHz）比 ch9（8GHz）传得远、覆盖更省锚点。

## 2 系统角色与硬件分工

系统由移动标签、8 个固定锚点、以及既有的基站回传链组成。三者职责严格分离：锚点只测距、标签只定位、基站只汇聚。

| 角色 | 硬件 | 职责 |
|-|-|-|
| **锚点 ×8**（Anchor） | base-3.0：ESP32-S3 + DWM3000，市电供电常开 | 纯 UWB TWR 响应者：被动应答标签发起的测距、回报测距帧，**不做任何定位解算**。各锚点烧录同一固件、仅 16 位短地址（mac16）不同。上电即初始化 DW3000（复位、PHY 配置、写入本颗已标定的天线延迟）→ 持续接收并自动重收 → 按 DS-TWR 应答（收 Poll 回 Response、收 Final 算距离并放进 Report 帧发回）。不持有场地坐标、不与其他锚点通信，因此加锚点只是加一个响应者，系统线性扩展。 |
| **标签 ×N**（Tag） | tag-3.0：ESP32-S3 + IMU + Si3933(LF) + DWM3000，电池供电 | 测距发起者 + **定位解算主体**：由 LF 过点唤醒进入工作态，轮询就近锚点拿距离，把逐锚距离作为量测喂进本机 ESKF，与 IMU 惯导紧耦合，实时输出 3D 位置。 |
| **基站**（Base station） | 既有基站 + 4G/WiFi | 只做汇聚回传：接收标签经 ESP-NOW 上报的 odom 状态量（含 3D 位置），经 4G 上云。**不参与实时解算**。回传链 base 端 tag 表 MAX_TAGS=32、tag_id 为 16 位，均非瓶颈。 |

**解算为什么放在标签端。**需求是"实时、精准的 3D 位置，且每个锚点的距离都参与实时 ESKF 更新"，而 ESKF 本就运行在标签端（IMU 高频惯导 + 多种量测插件，见核心算法文档）。只有把 UWB 距离与 IMU 在同一颗芯片上紧耦合，才能既补住惯导的长期漂移、又用惯导在测距间隙平滑外推，得到高频、低延迟的位置。若上报到基站／云再解算，会引入回传延迟、丢失与 IMU 的时间对齐、也拿不到 IMU 状态，无法满足"实时精准"。这与项目决策"边缘解算只传 odom 状态量、速度／位置靠每圈锚点校正"一致。

## 3 工作时序与 LF 过点触发耦合

标签的 UWB 测距不是长开的，而是与既有的 LF 过点计时链路耦合，形成"过起点开测、场内定位、过终点回睡"的生命周期。这么做既省电（DW3000 收发峰值约 150mA，必须在不需要时深睡，否则拖垮 LF 唤醒的低功耗预算），又天然限定了"此刻在场内、需要占用 UWB 空口"的标签集合。触发源即现有机制：标签骑过起点地感线圈→Si3933 收到 125kHz LF 唤醒→WAKE 上升沿中断在 ISR 里锁存微秒时间戳并入队（决策 A2、G28）。

耦合分三个层次，从必做到进阶：

| 耦合层次 | 作用 | 说明 |
|-|-|-|
| **① 生命周期开关**（必做） | 省电 + 只让在场标签占空口 | 过起点 LF 唤醒→激活 DW3000 开始 UWB 测距；过终点→停测、DW3000 回深睡。未进场的标签完全不占 UWB 信道，直接缓解多标签容量压力（见第 6 章）。 |
| **② 过点绝对位置校正**（推荐） | 每圈一次零漂校正 | 起点／终点线圈是已知固定坐标。过点瞬间给 ESKF 一个"此刻正好在 (x0,y0)"的强位置约束，把累积漂移清零。tag-3.0 固件已有此逻辑雏形（app_main 的每圈过点位置 snap）。详见第 4 章融合。 |
| **③ 触发入调度**（进阶） | 多标签错峰、减少碰撞 | 过点即"我进场了，请把我加入 UWB 测距轮转"。⚠️ 注意：加入的是**调度成员集合**，实际时隙节拍由**锚点广播的 beacon** 定，**不是**用 LF 过点时刻直接当 TDMA 时隙栅栏。 |

<callout emoji="💡">
边界：LF 耦合的是"生命周期 + 绝对位置校正"，**不是 UWB 的时钟同步**。DS-TWR（双边双向）本身抵消收发时钟偏移、无需节点间授时，这正是选它的核心理由；耦合 start 触发时务必保持这一免同步特性，不要把它退化成需要全场授时的方案。
</callout>

## 4 数据流与紧耦合解算

一个定位周期如下：标签被 LF 唤醒进场后，依次向就近锚点发起 DS-TWR（双边双向测距，抵消时钟偏移，无需锚点间授时），每完成一次拿到一个"锚点 ID + 距离"结果；每个距离一到达就作为一次**标量量测**触发 ESKF 更新（不必等齐全部锚点），IMU 则在两次量测之间以高频做状态传播；过起点／终点时再叠加一次绝对位置校正（第 3 章层次②）。ESKF 输出的 3D 位置随即打包进既有 odom 上报结构，经 ESP-NOW→基站→4G→云。

```text
IMU(200Hz) ─────────────┐
UWB 就近锚点距离 ─────────┼─► tag ESKF ─► 实时 3D 位置(x,y,z) ─► ESP-NOW ─► base ─► 4G ─► 云
LF 过点绝对位置(每圈一次) ─┘   (惯导传播 + 逐锚距离量测更新 + 过点位置校正)
```

UWB 距离在 ESKF 里按"标签当前位置到该锚点已知坐标的欧氏距离"建模为观测，逐锚更新即经典的紧耦合 UWB/INS。相比先凑齐距离再做一次最小二乘多边定位（松耦合），紧耦合在锚点被临时遮挡、只测到 3–4 个锚点时仍能靠 IMU 维持并用可得的距离修正，鲁棒性更好，正是选它的原因；也让 UWB 不必每标签高频（第 6 章容量的关键红利）。

## 5 天线延迟标定与坐标录入（厘米精度的硬门槛）

DWM3000 模组出厂 OTP 天线延迟为空，不标定会有几十厘米的系统性偏差，泵道尺度下尤为明显；标定后才能到厘米级。每颗模组（8 个锚点 + 每个标签）都要单独标定一次：把两颗设备放在已知的固定距离（如正好 5.00m），反复扫描天线延迟值，直到测距读数收敛到真实距离，再把该值写入固件／NVS。锚点坐标以及起点／终点线圈坐标也在部署时用卷尺／全站仪实测录入，作为解算与过点校正的已知量。

## 6 多 tag 容量与调度

UWB 是共享无线信道，同一时刻只能有一个标签在与锚点做测距，否则信号在空中碰撞。因此场地内可同时精定位的标签数不取决于地址空间，而取决于"空口时间预算"：每个标签每秒占用的测距时间之和不能超过一条信道的可用时间。下面按当前 8 锚点、10Hz（不损失轨迹精度的下限刷新率）估算。

### 6.1 空口时间账（8 锚点 / 10Hz / DS-TWR）

一次 DS-TWR 交换是 Poll→Response→Final 三帧加两端处理延迟；在 DW3000 常用配置（6.8Mbps、ch5）下，含处理间隙与保护时间，单锚一次测距约 2ms。据此：

| 项 | 数值 |
|-|-|
| 单锚一次 DS-TWR（含处理/保护） | 约 2 ms |
| 一个标签测完 8 锚一轮 | 8 × 2 ms = 16 ms |
| 10 Hz 下单标签每秒空口占用 | 16 ms × 10 = 160 ms/s（约 16% 信道） |
| 理论上限（100% 占满） | 1000 / 160 ≈ 6 个标签 |
| **实用上限（留 \~30% 给调度间隙/重传/多径重测）** | **约 4–5 个标签** |

结论：当前架构（单信道、8 锚点、每标签轮询全部 8 锚、10Hz）下，**不损失精度可稳定同时定位约 4–5 个标签**。这是空口物理时间决定的硬上限，不是软件常量（回传链的 MAX_TAGS=32、16 位 tag_id 都远不是瓶颈，改常量即可）。

### 6.2 提升标签数的手段

要在同一场地容纳更多标签，按性价比从高到低有以下几条，可叠加使用：

| 手段 | 容量收益 | 代价 / 说明 |
|-|-|-|
| **LF 过点门控（只让在场标签测距）** | 直接按"在场比例"缩减占用 | 第 3 章层次①的直接红利：没进场的标签零占空口。全天几十台车、场内同时仅数台时，等效把容量需求压到"同时在场数"。 |
| **IMU 紧耦合兜底 + 降低单标签测距率** | 数倍 | 位置由 IMU 高频外推，UWB 只需低频"校正锚点漂移"。把单标签测距从 10Hz 降到 2–3Hz，输出位置仍是 IMU 率的高频（精度基本不掉），容量随之翻数倍。几乎零成本。 |
| **每标签只测最近的 4 个锚（而非全 8）** | 约 2× | 定位数学最少 3 锚、稳健 4 锚即可；8 锚是为全场覆盖，任一位置实际只需就近 4 锚。单标签一轮从 16ms 降到 8ms，容量翻倍，精度不降。 |
| **TDMA 时分调度（锚点 beacon 定节拍）** | 吃满理论上限 | 给每个标签分配固定时隙轮流测距，消除碰撞与退避浪费。标签由 LF 过点触发加入轮转（第 3 章层次③），节拍由锚点广播 beacon 统一，而非 LF 时刻直接切片。 |
| **多信道并行** | 约 2×（ch5+ch9） | 标签与锚点分两组分别跑 ch5(6.5GHz) 与 ch9(8GHz)，两条信道互不干扰。需锚点双份或双频，成本上升。 |
| 缩短单次测距（SS-TWR / 短前导 / 高数据率） | 约 1.5–2× | SS-TWR 省一帧但需时钟补偿、精度略降；短前导／高速率降链路预算。泵道大场地慎用，作为余量手段。 |

<callout emoji="💡">
推荐组合：LF 过点门控 + IMU 紧耦合（单标签 2–3Hz UWB 校正）+ 就近 4 锚 + TDMA 调度，在单信道 8 锚点不加硬件的前提下，可把同时定位标签数从 4–5 个提升到 **约 15–25 个**；若仍不够，再上多信道并行翻倍。
</callout>

注：以上为基于 DW3000 典型时序的工程估算，实际值随最终 PHY 配置（数据率／前导长度／信道）、测距率设定与现场多径而变，量产前须实测标定。

## 7 固件现状与待实现项

底层已就绪：uwb 组件（含 vendored libdeca DS-TWR 内核 + decadriver），锚点角色（持续应答）与标签角色（发起测距、回调返回厘米距离）都已实现并通过主机孪生测试。要落地本方案，还需补齐以下标签端逻辑。

| 模块 | 状态 | 说明 |
|-|-|-|
| UWB TWR 内核（tag/anchor 角色） | 已实现 | components/uwb，DS-TWR 直出厘米，孪生测试全过 |
| LF 过点门控 UWB 电源/生命周期 | 待实现 | 第 3 章层次①：过起点唤醒开测、过终点停测回睡；复用现有 Si3933 WAKE 事件 |
| 过点绝对位置约束接入 ESKF | 部分（有雏形） | 第 3 章层次②：tag 固件已有每圈过点位置 snap，需接成 ESKF 的位置量测 |
| 多锚轮询 + TDMA 调度（锚点 beacon） | 待实现 | 第 6 章：就近选锚 + 时隙轮转；参考调研中 Makerfabs/kk9six 的 TDMA 多锚方案 |
| UWB 距离 → ESKF 量测插件 | 待实现 | 把逐锚距离接入 estimator 已预留的 UWB 量测接口，做紧耦合更新；需锚点坐标表 + 天线延迟标定值 |
| 接入 tag/base target | 待实现 | uwb 组件目前未接入 tag/base 的 app_main，接线与 sdkconfig 片段见组件 README |
