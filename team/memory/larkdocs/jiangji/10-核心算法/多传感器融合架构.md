# 多传感器融合架构（ESKF 主线）

> 运动数据 / 发力分析一侧的算法主线，贯穿全部阶段。核心思想：**按"算力位置"分层，不用一种框架打天下**。

## 一、分层算力架构

传感融合顺着"标签 → 边缘盒 → 云"的算力梯度切分，各层用最合适的框架：

| 层 | 硬件 | 传感器 | 框架 | 产物 |
|-|-|-|-|-|
| **标签端** | ESP32-S3（单核 FPU，512KB RAM，无 GPU） | IMU + 气压计 + LF 计时（+ 阶段二 UWB） | **ESKF**（误差状态卡尔曼） | odom 状态量：姿态 / 速度 / 腾空 / 过线微秒戳 |
| **边缘盒**（阶段三/五） | 真 SoC（Linux/ROS，有算力） | 相机 + 标签 odom + UWB | MSCKF 或因子图优化 | 厘米级轨迹 / 骨骼级动作 |
| **云端** | 云服务器 + 大模型 | — | AI 分析 | 发力分析 / 热力图 / 教练点评 / 高光裁剪 |

**一句话**：标签端 = ESKF（滤波）；边缘盒 = 视觉惯性（MSCKF/因子图）；云 = AI 分析。

```
标签端 ESP32-S3          边缘盒(阶段三/五)         云端
IMU+气压+LF+UWB    →     相机(VIO)+odom+UWB   →   AI 发力分析
   ESKF                  MSCKF / 因子图            热力图/点评
   ↓ odom 状态量          ↓ 厘米级轨迹              ↓ 高光短片
```

## 二、为什么标签端选 ESKF

| 框架 | 本质 | 状态规模 | 标签端可行 | 归属 |
|-|-|-|-|-|
| Madgwick/Mahony | 互补滤波，只估姿态 | 4 | ✅ | MVP / ESKF 姿态 bootstrap + 降级回退 |
| **ESKF** | 名义态传播 + 误差态线性化 + 量测更新 | 15\~21 | ✅ **实时无压力** | ⭐ **标签端核心** |
| MSCKF | 滑窗历史位姿 + 视觉零空间约束 | 几十\~上百 | ❌ 无 GPU/RAM 不够 | 边缘盒 VIO |
| 因子图优化 | 滑窗 BA / 全局优化，可回环 | 大 | ❌ | 边缘盒 / 云 |

**ESKF 的三个决定性优点**：

1. **误差状态天然处理四元数流形**——在切空间 SO(3) 更新，避免归一化/奇异；
2. **在线估计陀螺/加计零偏**，解决 IMU 积分漂移；
3. **量测更新做成插件**——气压高度 / UWB 距离 / 零速 / 轮速都是一次 `update(H, z, R)`，**加传感器不动主框架**，这就是"可扩展"的关键。

> ⚠️ **航向可观性**：量产不上磁力计 → 航向（yaw）不可观、会缓慢漂移。yaw 必须靠外部约束定：UWB 多锚点（阶段二）、每圈过线锚点重置、视觉（阶段五）。阶段一无 UWB 时 yaw 仅作相对参考，不追求绝对航向。

## 三、ESKF 状态定义

**名义状态**（在流形上积分传播）：

```
x = [ 位置 p(3)  速度 v(3)  姿态 q(4)  陀螺零偏 b_g(3)  加计零偏 b_a(3) ]
```

**误差状态**（15 维，切空间线性化，姿态误差用 3 维旋转矢量）：

```
δx = [ δp(3)  δv(3)  δθ(3)  δb_g(3)  δb_a(3) ]  →  协方差 P ∈ R^{15×15}
```

加 UWB 时延或多 IMU 外参在线标定时扩状态即可，**扩状态不改框架结构**。

**量测插件表**（每种传感器只实现观测函数 h(x)、雅可比 H、噪声 R）：

| 插件 | 观测 h(x) | 阶段 | 备注 |
|-|-|-|-|
| 气压高度 | 高度 p_z | 一 | 仅约束高度趋势，短跳不可靠，R 设大 |
| 零速 ZUPT | 速度=0 | 一 | 发车前静止，强约束零偏可观性 |
| 腾空 airtime | 0g 自由落体段 | 一 | 作事件而非连续更新 |
| UWB 距离 | ‖p − 锚点‖ | 二 | 多锚点同时约束位置与航向 |
| **轮速** | 车体纵向速度 = ωr | 二 | 速度精度杀手锏（详见轮速传感器专篇） |
| 视觉位姿 | p, q | 五 | 边缘盒回灌 |

## 四、固件语言：C++17（混合纪律）

上 ESKF 后矩阵运算是刚需 → 用 C++17 + 定长矩阵库（可替换 Eigen）。分层守纪律：

| 层 | 语言 | 约束 |
|-|-|-|
| ISR / 驱动热路径 | C 子集 | 无异常/无堆分配/无虚函数；ISR 只锁微秒戳 + 入队 |
| 驱动对外接口 | C 接口（extern "C"） | 保持 C ABI，便于单元测试 |
| 估计器/标定/初始化 | C++17 | 模板矩阵、强类型状态 |

**ESP32-S3 数值约束**：只有单精度硬件 FPU（double 是软件模拟）→ **全程 float**；大矩阵留内部 SRAM（ESKF 15×15 约 1KB，无压力）。

## 五、标定与初始化（工业级必备）

**标定**（结果存 NVS，开机加载）：

| 项 | 方法 | 何时做 |
|-|-|-|
| 陀螺零偏 | 静置取均值 | 每次开机 + 出厂 |
| 加计零偏/尺度/非正交 | 六面静置最小二乘 | 出厂一次 |
| 温度补偿 | 标零偏-温度曲线 | 出厂（户外温差大，必须做） |
| IMU→车体对齐 | 静止重力矢量定 roll/pitch 安装角 | 出厂 |

**初始化**（不做则 ESKF 一开机就发散）：

| 阶段 | 内容 |
|-|-|
| 静止检测 | 加速度模≈1g 且方差小 + 角速度模小，持续 N 帧（所有初始化的前置门控） |
| 静止初始化 | 重力对齐求初始 roll/pitch + 陀螺均值定零偏 + 设初始协方差 |
| 零速更新 | 静止段做速度=0 更新，强约束零偏 |
| 航向初始化 | 阶段一 yaw=0（相对参考）；阶段二 UWB 定 yaw |

## 六、性能实测（ESP32-S3 @240MHz，15 维）

| 项 | 值 |
|-|-|
| predict（每 IMU 帧） | \~86 µs |
| update（单量测） | \~92 µs |
| 每帧（predict + 加计重力 + 垂直约束） | \~290 µs |
| **CPU 负载 @200Hz / @400Hz** | **5.8% / 11.6%** 单核 |
| 内存（协方差/常驻/峰值栈） | 900B / \~1KB / \~4.5KB（全 SRAM） |

**结论**：标签端实时前向 ESKF 用不到 12% 单核，裕量充足。后向 RTS 平滑（更高精度）在边缘盒/云端跑，标签只出因果前向 odom。

## 七、落地状态

- ✅ 静止检测 + 重力对齐 + 陀螺零偏初始化；
- ✅ 六面加计标定 + 温补/外参接口 + NVS 存取（magic+版本+CRC32）；
- ✅ C++17 ESKF 框架（15 维、predict、统一 update + Joseph form、气压/零速/UWB/轮速/垂直约束插件），Madgwick 保留为 bootstrap/降级；主机孪生测试全通过；
- 待做：阶段二 UWB = 加一个距离 update 插件（接口已留）；阶段五视觉 = 边缘盒另起 VIO。
